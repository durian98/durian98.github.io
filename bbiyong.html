탐지 평가와 경보 시스템 구현

01

실시간 주행에 맞는 탐지 방식 비교

주행 중 화재를 놓치는 경우를 줄이려고 YOLO 단독 판독과 재판별(Cascade), 여러 형태로 바꾼 영상의 결과를 모으는 방식(TTA)을 같은 데이터에서 비교하는 도구를 만들었습니다. 재판별과 TTA를 결합한 방식의 종합 점수가 가장 높았습니다. 다만 화재 탐지의 정밀도·재현율 목표를 충족하지 못했고, 이 비교에는 여러 장을 읽는 데 걸리는 시간이 반영되지 않았습니다. 그래서 정확도 비교에 쓸 방식과 로봇에서 시험할 후보를 따로 골랐습니다.

Python · PyTorch · YOLO11n
02

로봇·관제·사건 영상을 하나의 경보로 연결

로봇이 보낸 경보를 저장한 뒤, 같은 사건 번호를 로봇 회신·관제 화면·사건 영상에 사용했습니다. 재접속으로 경보가 다시 들어와도 사건을 한 번만 저장하고, 외부 알림은 실패해도 사건 기록이 남도록 별도로 재시도하게 했습니다.

Spring Boot · MySQL · messageId / eventId
03

파트별 검증과 배포 자동화

백엔드·로봇·관제가 따로 변경되는 구조에 맞춰 파트별 검증과 배포를 구성했습니다. GitLab 병합 요청에서 빌드와 임시 MySQL 테스트를 실행하고, 개발 브랜치에 합쳐지면 변경된 파트만 배포하도록 했습니다. EC2에 Nginx와 Docker Compose로 실행 환경을 구성하고, 서버 준비 상태를 확인한 뒤 배포 결과를 공유했습니다.

EC2 · Nginx · Docker Compose · Jenkins
02

Jetson 최적화와 실제 주행 검증

학습 모델을 로봇 GPU에서 실행하도록 ONNX로 변환하고 TensorRT FP16으로 추론했습니다. 전열기를 시험용 열원으로 사용해 위험 감지부터 관제 경보까지 시험했습니다.

열원 감지부터 관제 경보까지

로봇이 회전하다 열원을 놓치거나 카메라가 열원 옆을 향하는 문제가 있었습니다. 제자리에서 천천히 도는 방법과 최근 이동 방향을 기억해 반대 방향으로 돌리는 방법을 시험했습니다. 열원을 다시 찾는 동작에는 최근 이동 방향을 활용하는 방식을 적용했습니다. 전열기를 시험용 열원으로 두고, 로봇이 감지한 경보가 관제 화면까지 전달되는 것을 팀과 확인했습니다.
