AI 활용

스킬과 프로젝트 기록을 연결해 반복 작업을 줄입니다

개요

Claude Code와 Codex를 기능 개발, 문서 작성과 디자인 작업에 활용합니다. 반복되는 절차는 스킬로 묶고, 프로젝트 기록을 다음 작업에 연결합니다. 필요한 기술 동향과 뉴스는 Discord 챗봇으로 모아봅니다.

01

프로젝트 기록과 작업 자동화

project-context-workflow · Obsidian MCP

다음 작업으로 이어지는 프로젝트 기록

프로젝트가 길어지면서 같은 배경을 다시 설명하거나 앞서 정한 결정을 놓치는 일이 생겼습니다. 프로젝트 개요, 설계 결정, 문제 해결 기록과 진행 상태를 나눠 남기고, 다음 작업에서 필요한 기록부터 읽도록 컨텍스트 관리 스킬을 만들었습니다.

Obsidian MCP로 기록을 연결해 쓰던 방식을 현재는 저장소의 지침과 스킬로 이어가고 있습니다. 새 대화를 시작할 때도 현재 구현과 결정 이유, 다음 작업을 불러와 이어서 진행합니다.

bbiyong-delivery

티켓·브랜치·MR 초안 준비 자동화

Jira 티켓 확인부터 파트별 기준 브랜치 확인, 구현·검증과 MR 초안 준비까지 BBIYONG 작업용 스킬로 묶었습니다. 저장소 규칙과 티켓 내용을 먼저 읽고, 변경 내용과 검증 결과를 커밋·MR 설명에 연결하도록 했습니다.

브랜치 기준과 문서 형식을 매번 설명하던 작업을 줄였습니다.

02

AI와 기능을 나눠 구현하기

Claude Code 서브에이전트 · Spring Boot · PostgreSQL

공통 기준을 정한 병렬 API 개발

GABOLLE의 여행 기록·피드와 동행 초대·공유 API를 만들 때 테이블, 저장소 인터페이스와 테스트 틀을 먼저 정해 커밋했습니다. 업로드 처리와 초대·공유 구현은 서브에이전트 둘에 나누고, 작업 폴더와 테스트 DB 스키마를 분리했습니다.

개인정보를 공개 응답에서 제외하는 정책은 직접 정했습니다. 생성된 코드를 읽고 테스트한 뒤 팀 브랜치에 반영했고, 팀의 MCP 도구로 파일을 선점해 동시 작업의 충돌을 줄였습니다.

learning-first-development · Spring Boot · JPA

일정 버전과 복사 규칙

일정을 편집하면 기존 일정은 남기고 새 버전을 저장하도록 정했습니다. 고정·제외·순서 변경·되돌리기에 같은 복사 규칙을 적용하며 AI와 구현했습니다. 안전장치를 하나씩 제거했을 때 테스트가 실패하는지 확인하면서 테스트를 454개에서 519개로 늘렸습니다.

가설 검토, 작은 단위의 수정과 실행 확인을 개발 스킬에 정리했습니다. 화면을 실제 사용 순서로 따라가며 코드 점검에서 놓친 버그 세 개를 찾은 뒤에는 화면 동작도 함께 확인하도록 작업 순서를 보완했습니다.

React Native · Expo

화면 공통 컴포넌트

여러 화면에서 쓰는 하단 시트와 사진 넘김을 AI와 공통 컴포넌트로 만들었습니다. 수정할 때도 같은 컴포넌트를 사용하는 화면에 함께 반영되도록 구성했습니다.

03

문서 작성과 디자인에 활용하기

korean-writing-editor

한국어 문서의 번역체와 반복 표현 교정

AI가 작성한 글의 번역체, 긴 수식어와 반복되는 추상적인 표현을 고치기 위해 한국어 편집 스킬을 만들었습니다. 제안서, 기획서와 보고서의 목적과 독자에 맞춰 초안을 편집할 때 사용합니다.

Codex와 Claude Code가 같은 스킬 원본을 읽도록 연결해 편집 기준을 한곳에서 관리합니다.

이 포트폴리오 · HTML / CSS · 반응형 화면

색상·여백·움직임을 공통 디자인 규칙으로

참고한 화면과 영상의 색상, 글자 크기, 여백과 움직임을 살펴보고 AI와 공통 스타일로 구현했습니다. 이번 포트폴리오에서도 세 가지 색상 시안을 비교한 뒤 화이트·오렌지·차콜을 선택하고, 제목과 본문, 휴대폰 프레임과 페이지 전환에 같은 규칙을 적용했습니다.

공통 스타일을 수정하면 여러 페이지에 함께 적용되도록 구성했습니다. 글의 배치와 이미지 비율은 PC와 모바일에서 확인해 조정했습니다.
