AI 활용

기능 개발과 검증, 프로젝트 기록과 반복 작업 자동화

작업 방식

Claude Code와 Codex를 기능 개발, 검증과 문서 작성에 사용합니다. 구현 전에 API와 데이터 처리 규칙을 정하고, 작업을 나눠 진행한 뒤 코드와 실제 화면을 확인합니다. 반복할 절차와 다음 작업에 필요한 기록은 재사용할 수 있는 작업 지침인 스킬로 관리합니다.

01

기능 개발과 검증

GABOLLE · Claude Code 서브에이전트 · Spring Boot · PostgreSQL

API 기준과 작업 범위를 먼저 정하기

여행 기록·피드와 동행 초대·공유 API를 개발할 때 테이블, 저장소 인터페이스와 테스트 틀을 먼저 정해 커밋했습니다. 업로드 처리와 초대·공유 구현은 AI 서브에이전트 둘에 나누고, 작업 폴더와 테스트 DB 스키마를 분리했습니다.

공개 응답에 개인정보를 포함하지 않도록 정책을 정하고, 생성된 코드를 읽고 테스트한 뒤 팀 브랜치에 반영했습니다. 동시에 같은 파일을 수정하지 않도록 팀의 MCP 도구로 작업할 파일을 먼저 선점했습니다.

GABOLLE 개발 내용 ↗
GABOLLE · Spring Boot · JPA · learning-first-development

일정 편집 규칙을 구현하고 테스트하기

일정을 편집하면 기존 일정은 남기고 새 버전을 저장하도록 정했습니다. 고정·제외·순서 변경·되돌리기에도 같은 복사 규칙을 적용하며 AI와 구현했습니다.

테스트가 일정 처리 규칙의 위반을 잡아내는지 보려고, 안전장치를 하나씩 제거한 뒤 테스트가 실제로 실패하는지 확인했습니다. 가설 검토, 작은 단위의 수정과 실행 확인을 개발 스킬로 묶어 이후 작업에도 적용합니다.

GABOLLE · React Native · Expo

코드 점검 후 실제 화면 흐름 확인

코드 연결을 점검한 뒤에도 화면을 실제 사용 순서로 따라가며 버그 세 개를 찾았습니다. 이후에는 화면 동작 확인을 작업 규칙에 추가했습니다.

여러 화면에서 쓰는 하단 시트와 사진 넘김도 AI와 공통 컴포넌트로 만들었습니다. 공통 요소를 고치면 사용하는 화면에도 함께 반영되도록 구성했습니다.

02

프로젝트 기록과 작업 자동화

project-context-workflow · Obsidian MCP

결정 이유와 다음 작업을 이어가기

프로젝트가 길어지면서 같은 배경을 다시 설명하거나 앞서 정한 결정을 놓치는 일이 생겼습니다. 프로젝트 개요, 설계 결정, 문제 해결 기록과 진행 상태를 나누고, 새 작업에서 필요한 기록부터 읽도록 컨텍스트 관리 스킬을 만들었습니다.

Obsidian MCP로 기록을 연결해 쓰던 방식을 현재는 저장소 지침과 스킬로 이어가고 있습니다. 새 대화에서도 현재 구현, 결정 이유와 다음 작업을 불러와 계속 진행합니다.

bbiyong-delivery · Jira · GitLab

티켓부터 코드 병합 요청 초안까지 연결

BBIYONG에서 티켓 확인, 기준 브랜치 확인, 구현·검증과 코드 병합 요청(MR) 초안 준비를 하나의 스킬로 묶었습니다. 작업을 시작하면 저장소 규칙과 티켓을 먼저 읽고, 변경 내용과 검증 결과를 커밋과 MR 설명에 연결하도록 했습니다.

파트별 브랜치 기준과 문서 형식을 매번 다시 설명하던 절차를 줄였습니다.

03

문서·디자인과 정보 수집

korean-writing-editor

문서의 목적에 맞춰 번역체와 반복 표현 교정

AI가 작성한 글의 번역체, 긴 수식어와 반복되는 추상적 표현을 고치기 위해 한국어 편집 스킬을 만들었습니다. 제안서, 기획서와 보고서를 작성할 때 목적과 독자에 맞춰 표현을 다듬는 데 사용합니다.

Codex와 Claude Code가 같은 스킬 원본을 읽도록 연결해 편집 기준을 한곳에서 관리합니다.

이 포트폴리오 · HTML / CSS · 반응형 화면

참고 디자인을 공통 스타일로 적용

참고 화면과 영상의 색상, 글자 크기, 여백과 움직임을 살펴보고 AI와 세 가지 시안을 비교했습니다. 화이트·오렌지·차콜을 선택한 뒤 제목과 본문, 휴대폰 프레임과 페이지 전환에 같은 규칙을 적용했습니다.

공통 스타일을 고치면 여러 페이지에 함께 반영되도록 구성하고, 이미지 비율과 글 배치를 PC와 모바일에서 확인했습니다.

Discord 챗봇 · 자동 수집·요약

기술 동향과 관심 분야 뉴스를 한곳에서 확인

최신 기술 동향과 관심 사업 분야 뉴스를 자동으로 수집·요약하는 Discord 챗봇을 구축해 사용하고 있습니다. 필요한 정보를 한 채널에서 받아보며 개발과 학습에 참고합니다.

04

데이터 분석과 모델 적용

학부 연구참여 · 데이터 분석 · VQA

데이터의 구조와 품질부터 확인

학부 연구참여에서 제조 데이터를 라벨링하고 전처리했습니다. 투구 기록에는 프로세스 마이닝을, 치안 설문과 지역 환경 데이터에는 다중회귀를, 실측 데이터의 유형 비교에는 K-Means 군집 분석을 적용했습니다.

이미지에 대한 질문에 답하는 VQA 과제에서는 식별하기 어려운 이미지 정리와 희소 라벨 보완을 제안해 학습 구성에 반영했습니다. 검증 데이터는 유지하고 학습 데이터에만 업샘플링을 적용했습니다.

반복 장면의 VLM 판독을 줄이는 프레임 선별

같은 조리 동작이 반복되는 동안에는 매 프레임을 시각언어모델(VLM)로 판독할 필요가 없습니다. 다양한 영상 분석 방법으로 동작이 바뀌는 지점을 추리고, 필요한 장면을 골라 판독하는 파이프라인을 개발하고 있습니다.

프레임 선별 방법과 비교 실험을 설계하고 공통 입력·평가 코드를 작성했습니다. 실제 VLM 판독을 포함한 시험에서 프레임 수, 토큰 사용량과 구간 검출 결과를 함께 비교하고 있습니다.
