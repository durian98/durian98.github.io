홈 소개 프로젝트 AI 활용 연락처

개발자 박재현입니다.

부산 여행 앱의 REST API를 만들었습니다. 화재 감지 로봇 프로젝트에서는 탐지 성능을 평가하고, 로봇이 보낸 경보를 관제 화면에 전달하는 백엔드를 구현했습니다. 조리 영상 프로젝트에서는 모델이 어떤 장면을 읽어야 하는지 실험하고, 평가 기준을 다듬었습니다.

팀으로 일할 때는 진행 상황을 자주 공유합니다. 의견이 갈리면 각자가 중요하게 보는 점을 먼저 듣고, 남은 시간 안에 함께 해결할 문제를 정합니다.

함께 일하는 방식

다시 나온 의견을 일정 안에서 검토

GABOLLE · 6명 팀의 팀장

여행 서비스의 방향을 정한 뒤 회의에 참석하지 못했던 팀원이 주제를 다시 검토하자고 했습니다. 팀원들의 의견을 정리해 공유하고, 이틀 정도 대안을 검토할 시간을 뒀습니다. 팀은 기존 주제를 유지하면서 새 의견을 반영해 서비스의 범위를 다듬었습니다.

웹과 AI 서버가 만나는 지점 맞추기

Arctic · 웹 API와 AI 서버 연동

병합 충돌이 반복되자 기능별로 담당을 나누고, 병합 전 절차를 팀과 같이 정했습니다. 웹 API와 AI 서버를 연결할 때도 요청·응답 형식을 함께 맞췄습니다.

현장에서 받은 피드백 반영

GABOLLE · FLY ASIA 창업박람회

앱 출시 후 투자자와 사용자에게 서비스를 보여주고 피드백을 받았습니다. 지도에서 여행 경로가 더 잘 보이도록 수정하고, 여행 생성에 불필요한 입력을 덜었습니다.

학습과 검증

통신 원리와 서버 보안 설정

백엔드와 인프라를 맡으며 OSI 계층과 소켓 통신, Nginx에서 요청이 분기되는 방식을 공부했습니다. BBIYONG에서는 EC2·Nginx·Docker Compose로 실행 환경을 구성하고, Jenkins로 파트별 검증과 배포를 연결했습니다. Nginx에는 동일 IP의 과도한 API 요청을 제한하도록 설정했습니다. 정상 요청은 통과하고, 한 IP에서 요청을 동시에 보냈을 때 일부가 제한되는지 응답과 로그로 확인했습니다.

UI·UX의 화면 배치와 동선

화면 배치와 내비게이션 바 구성을 공부하며, 선택할 수 있는 기능이 바로 보이는지와 원하는 기능까지 몇 단계를 거치는지 살폈습니다. GABOLLE에서는 이 기준으로 여행 생성 절차를 간소화하고, 주요 기능을 두 단계 안에서 찾도록 화면 동선을 검토했습니다.

객체 탐지 평가와 로봇 적용

객체 탐지의 평가 지표와 후처리 방식을 익히며, 탐지 기준별 결과를 비교하는 Python 평가 도구를 만들었습니다. 신뢰도와 중복 박스 제거 기준을 바꾸면서 오탐·미탐과 추론 비용을 함께 살폈습니다. 모델을 ONNX·TensorRT로 변환해 Jetson에서 실행하고, 실제 로봇을 움직이며 탐지 기준과 재포착 방식을 조정했습니다.
