레시픽

요리 영상을 단계별 레시피로 바꾸는 서비스

프로젝트 개요

조리 로봇을 학습시키려면 영상에서 ‘양파 볶기’ 같은 동작이 언제 시작하고 끝나는지 표시해야 합니다. 로보터블이 제시한 과제는 이 작업을 자동화하는 것이었습니다. 팀은 영상에서 동작이 바뀌는 시점을 찾는 파이프라인을 개발하고, 분석 결과를 직접 고칠 수 있는 요리 기록 앱 레시픽에 연결했습니다.

저는 반복되는 장면을 덜 읽고도 동작이 바뀌는 시점을 찾을 수 있도록 프레임 선별 방식을 설계하고 평가 코드를 작성했습니다.

영상에서 레시피 카드까지

영상을 올리면 레시픽이 ‘양파 볶기’, ‘소스 넣기’처럼 조리 단계를 나눕니다. 사용자는 영상을 보며 잘못 나뉜 단계를 고치고, 결과를 레시피 카드로 저장하거나 공유할 수 있습니다. 사용자가 고친 단계는 학습용 데이터의 검수 후보로 남기고, 원본 영상은 동의한 경우에만 학습에 쓰도록 설계했습니다.

조리 영상 분석 흐름

동작이 바뀔 만한 시점을 먼저 찾고, 그 주변을 자세히 읽습니다. 팀은 첫 단계에서 프레임 차분, 색상 분포, 영상 임베딩 등 후보를 찾는 방법 59가지를 영상 32편으로 비교했습니다. 영상 임베딩은 장면을 숫자 벡터로 표현해, 색이 비슷한 장면에서도 동작이 바뀌는 시점을 찾는 데 썼습니다.

  1. 1. 변화 후보 찾기영상 특징을 비교해 동작이 바뀌었을 만한 시점을 찾습니다.
  2. 2. 프레임 선별후보 앞뒤와 그 사이에서 판독할 장면을 고릅니다.
  3. 3. 장면 판독시각언어모델(VLM)이 고른 장면을 시간순으로 읽어 재료와 동작을 파악합니다.
  4. 4. 단계 확정판독 내용을 조리 작업 단위로 묶고 단계가 바뀌는 시각을 정합니다.

프레임 선별과 경계 평가

같은 동작이 이어지는 장면은 덜 읽기

계속 볶는 장면은 비슷한 프레임이 이어지지만, 소스를 넣는 순간은 짧아서 놓치기 쉽습니다. 그래서 동작이 바뀔 만한 시점의 앞뒤 2초는 촘촘히 읽고, 나머지 구간은 8초마다 한 장씩 읽도록 설계했습니다. 팀에서 함께 쓸 실행·평가 코드를 작성하고, 팀원과 영상 16편을 비교했습니다.

사람이 표시한 시점에서 5초 이내에 들어온 예측을 맞힌 것으로 봤습니다. F1은 놓친 경계와 잘못 잡은 경계를 함께 반영하는 점수입니다.

사람이 나누는 조리 단계에 맞춰 판독 기준 수정

놓친 경계 92개 중 64개에서는 앞뒤 장면을 모델에 보냈는데도 모델이 같은 단계 이름을 붙였습니다. 영상을 다시 보니 모델이 서로 다른 작업을 하나로 묶기도 하고, 사람이 한 단계로 보는 반복 동작을 여러 단계로 나누기도 했습니다.

‘양파를 여러 번 젓기’처럼 이어지는 동작을 한 단계로 보도록 판독 지시문을 고쳤습니다. 사람이 구분한 단계에 맞춰 정답 라벨을 만들고, 정답 경계 하나에 예측 하나만 대응하도록 평가 코드도 수정했습니다.

이 기준으로 다시 비교하니 변화 후보와 그 사이 장면만 읽어도 8초 간격 장면을 추가한 경우와 점수 차이가 크지 않았습니다. 그래서 더 적은 프레임을 쓰는 조합을 제안했습니다.

모델 학습과 앱 검증

조리 영상에 맞춘 추가 학습

초기 앱은 영상 한 편마다 Claude를 세 번 호출해 분석했기 때문에 비용과 호출 한도가 부담이었습니다. 팀은 Claude Sonnet으로 영상 클립 65개를 판독해 학습 예시를 만들었습니다. 이 예시를 바탕으로 자체 GPU에서 실행할 수 있는 Qwen3.5-27B에 LoRA 방식으로 장면 판독, 단계 묶기, 한국어 단계명 생성을 학습시켰습니다.

학습에 쓰지 않은 영상 23편에서 3초마다 한 장씩 입력해 학습 전후를 비교했습니다. 사람이 표시한 조리 단계와 비교한 동작 분할 적중률은 39.3%에서 54.0%로 높아졌습니다.

앱에서 영상 업로드부터 결과 공유까지 확인

앱은 자체 GPU에서 Qwen3.5-27B 기본 모델(FP8)로 1초마다 한 장씩 읽는 구성으로 검증했습니다. 영상 업로드부터 단계 저장, 결과 게시와 다운로드까지 확인했습니다.
