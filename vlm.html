조리 영상의 동작 구간 경계 검출 파이프라인 개발

조리 영상에서 동작이 바뀌는 시점을 찾아 로봇 학습용 구간으로 나눕니다.

2026.10.06–2026.11.18

프로젝트 개요

조리 로봇의 학습 데이터를 만들려면 영상에서 각 동작이 시작하고 끝나는 시점을 표시해야 합니다. 팀은 변화가 큰 지점을 먼저 찾고 필요한 장면을 시각언어모델(VLM)로 읽어, 사람이 검수할 조리 단계의 초안을 만드는 방법을 비교했습니다.

이 과제는 요리 기록 앱 레시픽으로 확장됐습니다. 영상에서 레시피 카드를 만들고, 사용자가 분석 결과를 직접 확인하고 고칠 수 있도록 했습니다.

담당 작업
프레임 선별·판독 실험, 사람 라벨과 평가 코드, 아이폰 웹 업로드 수정
개인 작업 기술
Python, VLM 평가, TypeScript, Java

조리 단계 분석 흐름

팀은 프레임 차분, 영상 임베딩과 변화점 탐지, 시간 합성곱 신경망(TCN)으로 경계 후보를 비교했습니다. 저는 후보를 받아 어디를 얼마나 읽을지 정하고, 판독 결과가 사람의 단계 구분과 얼마나 맞는지 검증했습니다.

  1. 변화 후보 검출영상에서 장면이 달라지는 시점을 찾습니다.
  2. 프레임 선별후보 근처는 촘촘히 보고 나머지 구간도 일정 간격으로 확인합니다.
  3. VLM 판독고른 장면에서 조리 동작과 재료 상태를 읽습니다.
  4. 단계 확정판독 결과를 작업 단위로 묶고 경계 시각을 정합니다.

제가 맡은 실험과 평가

필요한 장면을 골라 판독량 줄이기

변화 후보 전후 2초와 8초 간격 보완 프레임을 묶어 읽는 조건을 설계했습니다. 공통 입력·실행·평가 코드를 작성해 8편을 직접 실행했고, 팀원이 실행한 8편을 합쳐 16편을 비교했습니다. 1초마다 한 장씩 읽는 기존 방식 대비 토큰 사용량은 53%였고, 경계 시각 ±5초 기준 F1은 0.674 → 0.709로 실험에서 정한 성능 기준을 충족했습니다.

사람이 구분하는 작업 단위로 평가하기

놓친 경계 92개 중 64개는 모델이 양쪽 장면을 보고도 같은 단계로 분류한 경우였습니다. 사람 검수 라벨을 만들고, 지시문이 개별 움직임을 열거하는 대신 하나의 작업으로 묶도록 바꿔 비교했습니다. 사람의 조리 단계 기준으로 평가한 16편에서 변화 후보와 후보 사이의 중간 장면을 함께 읽는 조합을 제안했습니다. 이 결과는 연구 제안으로 정리했습니다.

요리 기록 앱 레시픽

팀은 레시픽에 자체 GPU에서 실행한 Qwen3.5-27B 영상 분석을 연결했습니다. 사용자는 영상을 올려 분석한 뒤 단계의 이름과 구간을 고치고, 레시피 카드로 저장하거나 공유할 수 있습니다. 사용자가 수정한 단계와 학습에 동의한 영상을 수집할 수 있게 설계했습니다.

아이폰 웹에서 대용량 영상 올리기

브라우저가 영상 전체를 복사하는 경로를 피하도록, 사용자가 고른 파일에서 업로드할 조각을 바로 읽게 수정했습니다. 서버에서는 영상의 표지 그림이 두 번째 영상으로 집계돼 업로드 확정이 거절되는 원인을 찾아, 실제 영상 트랙만 세도록 수정했습니다. iOS Chrome에서 15분 영상 업로드를 확인했습니다.
