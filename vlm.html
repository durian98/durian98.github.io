레시픽

요리 영상을 단계별 레시피로 바꾸는 서비스

2026.10.06–2026.11.18

프로젝트 개요

레시픽은 요리 영상을 올리면 ‘양파 볶기’, ‘소스 넣기’처럼 조리 단계를 나누고, 단계마다 이름과 시작·종료 시각을 붙여 주는 기록 앱입니다. 사용자는 원본 영상을 보면서 나뉜 구간과 이름을 고치고, 레시피 카드로 저장하거나 공유할 수 있습니다.

조리 로봇을 학습시키려면 영상에서 어떤 동작을 언제 했는지 표시한 데이터가 필요합니다. 팀은 사람이 검토할 단계 초안을 자동으로 만드는 실험에서 출발했습니다. 이후 요리하는 사람에게는 기록과 공유 기능을 제공하고, 팀은 사용자가 고친 단계와 학습 활용에 동의한 영상을 모을 수 있도록 앱을 만들었습니다.

기업 과제
조리 영상의 동작 구간 경계 검출 파이프라인 개발
담당
모델에 보여 줄 장면을 고르는 실험, 사람 기준 정답 작성, 단계 검출 평가 코드 구현
주요 기술
Python, 시각언어모델(VLM), Qwen3.5-27B, LoRA, Expo/React Native

촬영한 영상이 레시피가 되기까지

앱이나 웹에서 영상을 올리면 서버가 일정 간격으로 이미지를 뽑습니다. GPU에서 실행하는 시각언어모델(VLM)은 이 이미지들을 시간순으로 읽어 재료와 동작을 파악합니다. 이어 같은 작업에 해당하는 장면을 묶어 구간을 만들고 한국어 단계명을 붙입니다.

예를 들어 모델이 양파를 볶다가 소스를 붓는 장면까지 한 단계로 묶었다면, 사용자는 영상을 보면서 두 작업을 나눌 시점을 수정할 수 있습니다. 앱 서버는 사용자 수정과 학습 활용 동의·철회 이력을 저장합니다. 수정된 단계는 학습 데이터에 쓰기 전에 사람이 검수할 후보가 됩니다.

영상에서 조리 동작의 경계 찾기

영상에서 양파 볶기를 끝내고 소스를 붓기 시작한 시점을 찾는 것이 단계 경계 검출입니다. 초기에는 연속된 장면의 색이나 움직임 차이로 경계 후보를 골랐습니다. 소스를 붓는 장면은 잘 드러났지만, 비슷한 색의 재료를 뒤집거나 양념을 조금 넣는 장면은 놓치기 쉬웠습니다.

팀은 사람이 검수한 영상 32편에서 59가지 방법을 비교했습니다. Gemma로 영상 장면을 숫자 벡터로 바꾸고, KTS라는 변화점 탐지 방법으로 벡터가 달라지는 시점을 찾는 조합을 주요 비교 기준으로 삼았습니다. 이렇게 찾은 후보는 아래 분석 흐름의 출발점이었습니다.

  1. S1. 변화 후보 검출영상 특징을 비교해 동작이 달라졌을 만한 시각을 찾습니다.
  2. S2. 프레임 선별후보 주변을 촘촘히 보고 후보 사이에도 확인할 장면을 배치합니다.
  3. S3. VLM 판독선별한 장면을 시간순으로 묶어 재료와 조리 동작을 읽습니다.
  4. S4. 단계 확정이어지는 판독 결과를 작업 단위로 묶고 단계가 바뀌는 시각을 정합니다.

내가 맡은 실험과 평가

저는 팀이 찾은 변화 후보를 받아 어떤 프레임을 모델에 보낼지 정하는 S2부터, 판독 결과를 단계로 묶는 S4까지 실험했습니다. 후보가 있어도 그 장면을 모델에 보여 주는 방식이나 모델에 준 지시가 달라지면 최종 단계가 달라지기 때문입니다.

놓치는 단계가 늘지 않도록 판독할 장면 줄이기

변화 후보 전후 2초의 장면과 8초 간격의 보완 장면을 모델에 보내는 조건을 설계했습니다. 공통 입력·실행·평가 코드를 작성해 8편을 직접 비교했고, 팀원이 실행한 8편을 합쳐 총 16편을 분석했습니다. 1초마다 한 장씩 보내는 기준 방식 대비 토큰 사용량은 53%였습니다.

예측한 경계가 사람의 정답에서 5초 이내에 있으면 정답 후보로 인정했습니다. 놓친 경계와 잘못 잡은 경계를 함께 반영하는 F1 점수는 기준 방식 0.674, 프레임 선별 방식 0.709였습니다. 실험에서 정한 성능 유지 기준을 충족했습니다.

장면을 봤는데도 경계를 놓치는 이유

모델이 놓친 경계 92개를 살펴보니, 64개는 경계 양쪽을 보여 줬는데도 모델이 같은 단계로 판독한 경우였습니다. 프레임을 더 넣는 것과 별개로 모델이 어디까지를 한 단계로 보는지 살펴봤습니다. 같은 재료를 여러 번 젓는 동작은 하나의 작업으로 묶도록 지시문을 바꿨습니다.

사람이 영상에서 작업 단위의 경계를 직접 표시해 정답을 만들고, 예측과 정답이 일대일로 대응하도록 평가 코드도 수정했습니다. 새 기준으로 영상 16편을 비교했을 때, 작업 단위 지시문과 변화 후보 및 그 사이의 중간 장면을 사용한 조합은 F1 0.558을 기록했습니다. 8초 간격 장면까지 추가한 경우와 뚜렷한 점수 차이가 없어, 더 적은 장면을 쓰는 조합을 제안했습니다. 앞선 실험과는 정답에서 한 단계로 묶는 범위가 달랐습니다.

팀의 공개 모델 파인튜닝

초기 앱은 영상 한 편을 분석할 때 외부 API로 Claude를 세 번 호출했습니다. 판독 내용을 더 큰 모델에 다시 확인하는 실험까지 더해지자 비용과 호출 한도가 제약이 됐습니다. 팀은 자체 GPU에서 분석할 수 있도록 공개 모델 Qwen3.5-27B를 선택하고, 조리 영상에 맞게 추가 학습하는 실험을 진행했습니다.

Claude Sonnet의 답을 학습 데이터로 만들기

팀은 65개 학습 클립에서 3초마다 이미지를 뽑아 12장씩 묶고, Claude Sonnet의 답을 학습 예시로 만들었습니다. 첫 실험에서는 재료와 동작 판독을 학습했습니다. 후속 실험에서는 장면 판독, 조리 단계 묶기, 한국어 단계명 생성을 하나의 LoRA 어댑터에 학습했습니다. LoRA는 기본 모델의 가중치를 유지한 채 소규모 파라미터를 별도로 학습하는 방식입니다. 평가 영상 23편은 학습 자료와 분리했고, 채점에는 사람이 확인한 정답을 사용했습니다.

학습 전후 비교

재료 적중률 55.0% → 77.5%
평가 영상 중 팀 촬영 영상 16편에서 사람이 표기한 재료를 모델이 맞힌 비율입니다.
동작 분할 적중률 39.3% → 54.0%
영상 23편에서 모델이 나눈 20초 이상 구간을 평가했습니다. 구간 길이의 25%와 75%에 해당하는 두 시점이 사람의 같은 단계에 들어오면 적중으로 계산했습니다.

두 수치는 3초 간격 입력으로 평가한 Qwen3.5-27B의 학습 전후 결과입니다. 1인칭 영상에서 재료를 놓치거나, 보이지 않는 재료를 이름에 넣고 서로 다른 작업을 길게 합치는 오류는 남았습니다.

서비스 적용과 최종 결과

11월 14일 운영 검증에서는 자체 GPU에 올린 Qwen3.5-27B FP8 기본 모델로 1초마다 뽑은 장면을 분석했습니다. 긴 영상은 여러 조각으로 나눠 동시에 판독했습니다. 이 환경에서 영상 업로드, 단계 저장, 결과 게시·다운로드까지 확인했습니다. 앞 절의 파인튜닝 점수는 LoRA 어댑터를 적용하고 3초 간격으로 입력한 별도 실험에서 나온 결과입니다.

11월 18일 최종 발표에서 영상 한 편이 편집 가능한 조리 단계와 공유용 레시피로 바뀌는 과정과 모델 실험 결과를 소개했습니다. 프로젝트는 분석 결과를 사람이 고쳐 쓸 수 있는 서비스와, 동의받은 영상 및 단계 수정 기록을 다음 라벨 검수에 활용할 수 있는 구조를 남겼습니다. 실제 사용자 데이터로 모델을 다시 학습시키는 작업은 후속 범위였습니다.
